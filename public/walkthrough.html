01

Version detail: current child resume

The attached lesson uses an older Agent resume description. In the pinned current runtime, resume the parent query with options.resume and continue its child through SendMessage({to: agentId, message}). A new Agent invocation creates a new instance. Verify stable child IDs instead of assuming a successful parent answer proves resume.

02

Four identifiers

session_id belongs to the parent conversation. The Agent tool-use ID identifies a delegation. parent_tool_use_id links nested messages to that delegation. agent_id identifies the actual child and remains stable across a real continuation.

03

Automatic versus explicit

The automatic task does not name a specialist but asks the parent to choose by description. The explicit task names security-reviewer. Delegation is observed model behavior; the app does not implement a fake router or guarantee identical selections on every model.

04

Runtime factory and model access

Balanced uses the sonnet alias; strict uses opus. Both have Read/Grep/Glob and no editing or shell capability. Inspect actual model IDs. Aliases and account availability vary; this is an educational comparison, not a controlled quality or cost benchmark.

05

Child history proof

Resume discovers three routes, then asks the same child about /orders/:id without additional reads. The follow-up guard rejects new Agent calls and file tools. Evidence must show the same agent_id, the original parent session and a SendMessage addressed to that child.

06

Tool scope and troubleshooting

Review tools are read-only. The test runner may execute only node --test auth.test.cjs. Programmatic definitions override same-name project agents. New .claude/agents directories need session restart; verify YAML and unique names when agents do not load.

07

Partial output and lifetime

A child maxTurns limit can produce a partial report; that is not equivalent to completed work. Custom or general-purpose agents support continuation; Explore and Plan are one-shot. This lab bounds turns and removes all temporary transcripts after the experiment, so its captured IDs are explanatory evidence, not a permanent external resume API.
